# Bandwidth kernel `tsr_bw_k4` and host tool `tsr_bw`

The bandwidth kernel measures how much bandwidth one DDR4 channel, and all four channels together, deliver to a kernel clocked
like the Tesseract core, for reads, writes and both at once. This document describes the kernel, its packaging and build, the
bench that verifies it and the host tool `tsr_bw`. The kernel does not contain the core. It reuses only the platform adapter's
reset, register slices and AXI4 bridge ([platform-u200.md](platform-u200.md) §4, §5). Unlike the core kernels (`ap_ctrl_none`),
`tsr_bw_k4` is its own kernel with `ap_ctrl_hs` and an interrupt. `tsr_bw` builds with `-DTSR_WITH_XRT=ON`.

## 1. What the kernel measures and how

One channel (one DDR4 bank, 64 B at the core clock per direction at the AXI port) and all four channels together are driven for
reads, writes and both at once, over transfer sizes, burst lengths, the number of bursts in flight and the number of AXI IDs. The
kernel counts cycles itself, from the cycle its first request can be generated to its last response, per channel and direction, so
launch overheads (XRT, PCIe) are not in the number. The host tool also reports the wall-clock rate. Every run is checked: read
data by a checksum, written data by reading it back, status and error responses.

The kernel uses the same AXI bridge as the Tesseract kernels (`tsr_xrt_axi_bridge`: 2 register slices per AXI channel, AxCACHE
0011, 4-bit IDs, the same `sp=` bank binding as `hw/u200/k4.cfg`) and, in its default packaging, the same `m_axi` interconnect
hints (`MAX_BURST_LENGTH` 64, `NUM_READ_OUTSTANDING` 16, `NUM_WRITE_OUTSTANDING` 32), which the `v++` linker uses to size the
kernel-side interconnect. `lint.sh` checks that the two packagers agree. The kernel therefore sees the memory the way the core
does. The engine keeps up to 64 bursts in flight per direction, so the outstanding sweep above 16 reads and 32 writes shows what
the core's interconnect allows. A second packaging with 64 and 64 hints (`wide`, §4) is for comparison only. Record which xclbin
every number comes from.

## 2. Kernel interface and register map

The kernel is a Vitis RTL kernel `tsr_bw_k4` (module name is the kernel name) with `ap_ctrl_hs`, `ap_clk`, `ap_rst_n` (active low,
synchronous) and `interrupt`. `s_axi_control` is AXI4-Lite with 32-bit data and a 12-bit address (range 0x1000), and
`m_axi_ch0..3` are AXI4 with 512-bit data, 64-bit address and 4-bit ID, the signal list of the Tesseract kernels. The packaged top
has `NUM_CH` 4, `ADDR_BEAT_W` 28 (16 GiB per channel), `AXI_SLICES` 2 and `CTRL_PIPE` 2.

`s_axi_control` registers (byte offsets decoded on bits [11:2]; unmapped offsets read 0 and ignore writes; every response OKAY;
writable registers honour WSTRB):

| Offset | Name | Access | Content |
|---|---|---|---|
| 0x000 | AP_CTRL | | as Vitis `ap_ctrl_hs` (UG1393): bit 0 ap_start (a write of 1 sets it, cleared when the start is accepted, and ap_idle drops in the same edge), bit 1 ap_done (COR), bit 2 ap_idle, bit 3 ap_ready (COR), bit 7 auto_restart (not supported) |
| 0x004, 0x008, 0x00C | GIE, IER, ISR | RW, RW, R (toggle on write) | interrupt = GIE & IER[0] & ISR[0]. ISR[0] is set at completion while IER[0] = 1 |
| 0x010 | `seed` | RW, arg | pattern seed (all channels) |
| 0x020 + 0x20 c | `ctrl<c>` | RW, arg | bit 0 enable, bit 1 read, bit 2 write, [14:8] burst beats B (1 to 64), [22:16] outstanding bursts per direction (1 to 64), [26:24] id_log2 (0 to 4). Other bits are ignored |
| +0x08, +0x10, +0x18 | `bytes<c>`, `rd_off<c>`, `wr_off<c>` | RW, arg (u64) | bytes per direction, and the byte offsets of the read and the write region in the channel's buffer |
| 0x0A0 + 8 c | `ch<c>` | RW, arg (u64, `void*` on `m_axi_ch<c>`) | device address of the buffer bound to channel c (XRT: the buffer object's address) |
| 0x0F0 | BW_VERSION | R | `{16'h4257 ("BW"), 8'h01, 8'(NUM_CH)}` = 0x42570104 |
| 0x0F4 | BW_INFO | R | `{16'd0, 8'(ADDR_BEAT_W), 8'(AXI_SLICES)}` = 0x00001C02 |
| 0x0F8, 0x0FC | TOTAL_CYCLES | R (u64) | cycles from the accepted start to ap_done |
| 0x100 + 0x40 c | result block of channel c | R | below. Cleared at every start, final at ap_done (read through registered paths, so a register read is 3 cycles slower) |

Result block (offsets inside the block):

| Offset | Name | Content |
|---|---|---|
| +0x00 | STATUS | bit 0 RAN (enabled, configuration valid), bit 1 CFG_ERR (enabled, configuration refused, no traffic), bit 2 RRESP (at least 1 R beat with RRESP other than OKAY), bit 3 BRESP (the same for B), bit 4 UNEXPECTED (a response without an outstanding request was dropped by the bridge, also set by one arriving between runs), bit 5 DONE (the channel finished this run) |
| +0x04 | ERRS | [15:0] R beats with RRESP other than OKAY, [31:16] B with BRESP other than OKAY (saturating) |
| +0x08, +0x10 | RD_CYCLES, WR_CYCLES (u64) | cycles from go to the last R beat or the last B (§3). 0 without reads or writes |
| +0x18, +0x20 | RD_BYTES, WR_BYTES (u64) | R beats received * 64, W beats sent * 64 |
| +0x28 | CHECKSUM (u64) | read checksum (§3) |
| +0x30, +0x34 | RD_LAT, WR_LAT | cycles from go to the first R beat or the first B |
| +0x38, +0x3C | RD_BURSTS, WR_BURSTS | completed read bursts (last beats), B responses |

The kernel arguments (`kernel_bw_k4.xml`, ids in this order; XRT writes every one before each start) are `seed` (0), then per
channel `ctrl<c>`, `bytes<c>`, `rd_off<c>` and `wr_off<c>` (1 to 16), then `ch0` to `ch3` (17 to 20). The result registers are not
arguments. The tool reads them with `xrt::kernel::read_register`, which needs exclusive compute-unit access. The transport opens
the core kernels with `xrt::ip` ([xrt-host.md](xrt-host.md) §4.1).

## 3. Behaviour

- Start. `ap_start` while idle is accepted in the next cycle. All arguments are latched as a snapshot, so later register writes do
  not affect the run. A toggle goes to the four engines through `CTRL_PIPE` register stages. Each engine latches its
  configuration, checks it (3 cycles) and starts generating at go. When every engine has returned the toggle, `ap_done`,
  `ap_ready`, `ap_idle` and ISR are set. `ap_start` written during a run stays pending. Disabled channels finish at once.
- Configuration check, for enabled channels. A failure sets CFG_ERR and generates no traffic, and the other channels run normally.
  The checks are that the mode (read and write bits) is not 0, B and outstanding are in 1 to 64, `id_log2` is at most 4, the
  buffer address is 4 KiB aligned, `bytes` and the offset of every enabled direction are multiples of 64, and every enabled region
  ends at most at 2^(`ADDR_BEAT_W` + 6) bytes. The kernel does not know the buffer size, so the regions must lie inside the
  buffer, which the tool ensures. `bytes` = 0 is a valid empty run, also with an offset exactly at the limit. An offset beyond the
  limit is refused.
- Burst sequence, per direction and the same for AR, AW and the W beats. From the region's first beat a, the length is min(B,
  beats to the next 4 KiB boundary, beats left) and a advances by it. No burst crosses 4 KiB, some bursts are shorter than B when
  the region start is unaligned or B does not divide 64, and the region is covered exactly once. `burst_len` and `burst_count` in
  `tsr_bw_regs.h` are the reference. Requests go out at up to one burst per cycle per direction.
- IDs. Burst k of a direction uses AXI ID k mod 2^`id_log2`, with the read and write sequences counted separately. R beats of
  different IDs may interleave. The engine counts per beat, completes per RLAST and uses an order-independent checksum.
- Outstanding. A burst counts from its generation to its last R beat (its B). At most `outstanding` bursts per direction are in
  flight at the AXI port.
- Write data. W beats are in burst order, and the W beats of burst k start only after AW k was generated (W may still reach the
  AXI port before AW k is accepted, as AXI allows). The 64-bit word at byte offset o of the buffer (8-aligned, from the buffer
  address, not the device address) is `mix64(o ^ salt)` with `salt = seed << 32 | channel` and `mix64` one xorshift64 step (`x ^=
  x << 13; x ^= x >> 7; x ^= x << 17`). It is invertible and linear over GF(2), so the hardware computes one `mix64` per beat and
  XORs constants: word i of the beat at o is `mix64(o) ^ mix64(8i) ^ mix64(salt)`. Every word encodes its own location, channel
  and seed, so a missing, misplaced, duplicated or bit-corrupted write shows up as a mismatch.
- Read checksum. The sum over the received beats of the sum over i of `rotl64(w_i, 8 i)` (mod 2^64), with words in little-endian
  byte order. It is independent of the arrival order of beats and sensitive to every bit, to the word position in a beat and to a
  duplicated or missing beat.
- Cycles. The engine's counter is 1 in the first cycle of go and counts every cycle. `RD_CYCLES` and `WR_CYCLES` are its value in
  the cycle the engine sees the last R beat or B, and `RD_LAT` and `WR_LAT` its value in the cycle of the first. The engine sees
  responses after the bridge's response slices. With a memory that answers in the cycle after the request, the first R beat
  reaches the engine `2 * AXI_SLICES + 4` cycles after go (§5.2), so a transfer of N beats at full rate takes N + 7 cycles for
  reads and N + 8 for writes. Bandwidth is bytes divided by cycles divided by the clock frequency.
- Errors. R and B responses with RRESP or BRESP other than OKAY are counted (ERRS) and flagged (STATUS). A response without an
  outstanding request is dropped by the bridge's ID filter and flagged (UNEXPECTED). There is no abort. A run that never
  completes, for example with a stuck interconnect, needs a card reset (`xbutil reset`), and the tool says so on its timeout.
- Reset. `ap_rst_n` stays low for at least 3 cycles, the AXI-side bound of [platform-u200.md](platform-u200.md) §5. This kernel
  has no core and no `RST_PIPE`, so the 4-cycle minimum of the Tesseract kernels does not apply. After a reset every register,
  argument and result is 0 and there is no AXI traffic.

## 4. Implementation, packaging, build

RTL. `tsr_bw_kernel` is `tsr_xrt_reset` (the adapter's, with per channel 13 equal reset copies: 12 for the parts of the bridge and
one for the engine and its toggles, [platform-u200.md](platform-u200.md) §8.2), `tsr_bw_ctrl`, and per channel a `tsr_bw_engine`
feeding a `tsr_xrt_axi_bridge`. Everything between the control block and an engine is registered on both sides (toggles through
`CTRL_PIPE` stages, a static configuration snapshot, a registered result path), so each channel can sit in the SLR of its bank.
The generators walk the burst sequence with the beat address split into block index and offset inside the 4 KiB block and a
down-counter of blocks to the region end, so the one-burst-per-cycle loop has no wide subtract. The checksum is a registered 8 to
4 to 2 to 1 adder tree plus the accumulator, and the pattern is one registered `mix64` per beat and an XOR. `filelist.f` is
complete, and no technology wrapper is involved. `gen_bw.py` writes `tsr_bw_k4.v`, `kernel_bw_k4.xml` and the bench wrapper from
one table, and `gen_bw.py --check`, run by `lint.sh`, fails on a stale file.

Packaging. `rtl/platform/alveo_xrt/bw/package_bw_xo.tcl <repo> <outdir> [core|wide]` follows the flow of the adapter's
`package_xo.tcl` (IP packager, Vitis kernel properties, the m_axi hints, the register map with the arguments, integrity checks,
the source manifest `tsr_bw_k4.sources.sha256`) and writes `build/u200/xo/tsr_bw_k4.xo`. The hints are `core` (default), the
Tesseract kernels' 64, 16 and 32, and `wide`, 64, 64 and 64, which writes `build/u200/xo/wide/tsr_bw_k4.xo`.

Build. `hw/u200/bw/build_bw_xclbin.sh [hw|hw_emu]` (`TSR_BW_HINTS=core` by default, or `wide`) repackages the `.xo` when it is
missing, was packaged with other hints, or its source manifest no longer matches the working tree. It then runs `v++ --link
--config hw/u200/bw/bw.cfg` and writes `build/u200/bw/tsr_bw_k4.xclbin` (`build/u200/bw_wide/` for `wide`). `bw.cfg` has
`kernel_frequency=300`, one compute unit `tsr_bw`, `sp=tsr_bw.m_axi_ch<c>:DDR[c]` and no `slr=`. `TSR_BW_FLOORPLAN=1` adds the
draft `bw_floorplan.tcl`, which is not used for the xclbin and not needed for timing. Platform lookup and `TSR_VIVADO_LOCK` are
those of `hw/u200/build_xclbin.sh`.

### 4.1 Packaging and the link

A packaging is checked by `ipx::check_integrity` (kernel and xrt), by the 12-file manifest matching the working tree, by the 9 HDL
sources inside the `.xo` being byte-identical to the repository, and by `component.xml` carrying `FREQ_HZ` and the m_axi hints on
all four `m_axi_ch<c>`. `tb/platform/bw/viv/bw_ooc.tcl ... impl` runs `tsr_bw_k4` alone out of context on xcu200-fsgd2104-2-e
(`ap_clk` 3.333 ns, every I/O budgeted 1.6 ns outside). The linked xclbin maps `ch0..3` to bank0..bank3, 16 GiB each at
0x4000000000 + 0x1000000000 * c, uses no BRAM, URAM or DSP, and places all four engines and bridges in SLR1 when no floorplan is
given.

## 5. Verification

### 5.1 Bench (`tb/platform/bw`)

`bw_bench.cpp` is a Verilator C++ bench (the class `Vbw` is `tsr_bw_kernel` with any parameters, or the packaged `tsr_bw_k4`
behind `kwrap_tsr_bw_k4.sv`), built and run by `run_bw.py`.

- The host is an XRT-like AXI4-Lite master (class XrtHost, random VALID delays, early and late BREADY and RREADY, checks of the
  slave). It writes the whole argument map like XRT, then AP_CTRL = 1, and completes by interrupt or by polling.
- The memory is the adapter's `fr::MemModel` (`tb/fastreplay/memmodel.h`) behind an AXI4 translation, with the 16 AXI IDs mapped
  onto the model's 8 read and 4 write ids, which is stricter than AXI. The regimes are `ideal` (latency 0, every READY and VALID
  1), `fast`, `rand`, `slow` and `ordered`. Buffer addresses are random 4 KiB aligned values up to near 2^64. SLVERR, DECERR and
  stale responses are optional.
- The AXI4 checks are VALID and payload held, SIZE 6, INCR, CACHE 0011, PROT, LOCK and QOS 0, aligned, inside the buffer, LEN at
  most 63, no 4 KiB crossing, WSTRB all ones, WLAST, and nothing during or right after reset. Every AR and AW equals the next
  burst of the reference sequence, in-flight bursts stay within `outstanding`, and a disabled or refused channel has no traffic.
  Per run every result register is checked against the reference, the written region is bit-exact and complete, nothing is written
  outside it, the kernel is quiescent at completion and no RTL assertion fires. In the ideal regime with 64 outstanding the
  streaming is exact (§5.2).
- The tests (`--test`) are `regmap`, `single`, `all4`, `combos` (bursts 1 to 64, outstanding 1 to 64, IDs 1 to 16, unaligned
  regions, random multi-channel runs), `ideal`, `cfgerr` (invalid configurations, the legal limit, `bytes` = 0 at the limit),
  `errors` (SLVERR, DECERR, stale R and B), `apctrl` (back-to-back runs, result clearing, the snapshot against a fast host,
  queued `ap_start`), `reset` and `big` (16 MiB read and write on all channels). The default run is `--test all --regime all` for
  several seeds on the packaged top and on parameter variants. `pytest tb/platform/bw -m "not slow"` is part of `tb/run_all.sh`.
  The tool tests run only when a `tsr_bw` binary is given in `TSR_BW_BIN`.

### 5.2 Ideal-memory timing

With an ideal memory (latency 0, every READY and VALID 1) a channel moves one beat per cycle per direction. `RD_CYCLES` is the
beats + 7 for every burst length and `WR_CYCLES` is beats + 8, the same on every channel when all four run at once. The first
response arrives at `RD_LAT` 8 and `WR_LAT` 8 + the first burst length. The fixed part scales with the register slices: read
cycles minus beats is 2 * `AXI_SLICES` + 3 and write is 2 * `AXI_SLICES` + 4. `TOTAL_CYCLES` adds 15 cycles of start and
completion handshake. With one burst in flight a 64-beat read burst takes 71 cycles and a 1-beat read 8 cycles, and full rate
needs 2 bursts of 64 beats in flight (reads and writes), or 8 one-beat reads or 16 one-beat writes. These are the kernel's own
limits.

### 5.3 Mutation campaign (`tb/platform/bw/mutate_bw.py`)

Every mutant is one textual change of `tsr_bw_engine.sv` or `tsr_bw_ctrl.sv` in a scratch copy, run through regmap, single, all4,
combos, ideal, cfgerr, errors, apctrl and reset in the ideal, rand and slow regimes, stopping at the first failure. The unmutated
copy passes, and every mutant is killed except three equivalent ones. The killed classes are the reference burst sequence (a 4 KiB
limit one beat short, min and max swapped, a block carry lost, the ID mask ignored, bursts past the region end), the AXI4 checker
and memory model (bursts across 4 KiB, WLAST one beat early, traffic on refused channels), in-flight bursts above outstanding, the
written region against the pattern (carry, salt, word order, a wrong `mix64` shift, the seed lost in the snapshot), the checksum
and result registers, the ideal-memory streaming check, status, errors and completion (`bytes` = 0 at the limit, RRESP or BRESP
not counted, stale responses not flagged, done without the writes), and `ap_ctrl_hs` and the register map (clear on read, ISR
without IER, interrupt without GIE, byte strobes ignored, TOTAL_CYCLES not counted).

The equivalent survivors are `E_w_no_ahead`, W beats that may start before their AW was generated, which is legal AXI4 and gives
the same beats and bursts. `C_snapshot_live`, where the engines take the live argument registers instead of the snapshot: they
latch them `CTRL_PIPE` + 1 cycles after the accept, before the AXI4-Lite slave can complete another write at `CTRL_PIPE` 2, and
with `CTRL_PIPE` 4 the `apctrl` race test kills it. And `E_cs_nodrain`, where the channel reports done before the checksum
pipeline has drained: the pipeline drains 3 cycles after the last beat, while completion needs the toggle stages, `ap_done` and an
AXI4-Lite read before the host can read the checksum. The drain stays, correct by construction.

### 5.4 Lint

`rtl/platform/alveo_xrt/bw/lint.sh` runs `gen_bw.py --check` and Verilator `-Wall` runs of the engine, the control block and the
body with edge parameters (1 to 4 channels, `ADDR_BEAT_W` 7, 20, 28 and 52, `AXI_SLICES` 1 to 4, `CTRL_PIPE` 1 to 4, `CNT_W` 33
and 64), the packaged top and the bench wrapper. The only waiver is `SYMRSVDWORD` on the `interrupt` port.

## 6. Host tool `tsr_bw` (`sw/tools/tsr_bw.cpp`)

```
cmake -S . -B <build> -DTSR_WITH_XRT=ON [-DTSR_XRT_ROOT=...]   # docs/xrt-host.md §7
cmake --build <build> --target tsr_bw
TSR_XCLBIN=build/u200/bw/tsr_bw_k4.xclbin <build>/bin/tsr_bw [options]
```

| Option | Default | Meaning |
|---|---|---|
| `--xclbin F`, `--device N\|BDF`, `--kernel K` | `$TSR_XCLBIN`, `$TSR_XRT_DEVICE` or 0, `tsr_bw_k4` | |
| `--sizes LIST` | `1M,16M,256M,1G` | bytes per channel and direction |
| `--bursts LIST` | `1,4,16,64` | burst length in beats |
| `--outstanding N`, `--ids N` | 32, 1 | bursts in flight per direction, AXI IDs (1, 2, 4, 8, 16) |
| `--modes LIST` | `r,w,rw` | read, write, both at once |
| `--channels LIST\|none`, `--no-all` | every channel alone, then all together | |
| `--reps N` | 3 | repetitions. The median (by the slowest channel) is printed, and every run goes to the CSV |
| `--sweep-outstanding` | off | outstanding 1 to 64 at bursts 64 and 1 (latency-bound rates) |
| `--pcie` | off | host to card DMA rate per channel (`xrt::bo` write and read of 256 MiB, wall clock) |
| `--verify sample\|full\|none` | sample | read-back of written regions: all, or 4 MiB at both ends plus 8 random 4 MiB pieces |
| `--clock-mhz F` | the xclbin's DATA clock | clock frequency for the GB/s figures |
| `--ch-mib N` | 2 * the largest size | buffer per channel (device-only, in the bank of `ch<c>`) |
| `--csv FILE`, `--seed N`, `--timeout-ms N`, `-v` | | |
| `--mock` | | the C++ model of the kernel instead of a device, to test the tool (`TSR_BW_MOCK_FAULT=csum\|write\|status\|bytes`) |
| `--dry-run` | | open the device (xclbin, kernel, arguments, buffers) and complete one empty run |

The tool checks the xclbin (kernel lookup, one compute unit, `ap_ctrl_hs`, every argument by name with the offset and size of
`tsr_bw_regs.h`, `BW_VERSION`, the DATA clock), allocates one device-only buffer per channel, runs a self-check per channel (host
random data read by the kernel, and a kernel write read back by the host), fills the read region of every channel with the
pattern, and then runs every mode, size and burst for each listed channel alone and for all channels together, `--reps` times.
Each run is checked (status, error responses, bytes and burst counts, checksum, cycles, written region). The output per point is
mode, channels, size, burst, outstanding, the read, write and sum GB/s by the kernel's cycles, the percentage of 64 B per cycle
per direction, wall-clock GB/s, first-beat latencies, and ok or FAIL. Exit status 0 means all checks passed, 1 a check failed and
2 a setup error. It reads AP_CTRL until idle first, because accepting a start does not clear `ap_done`, so a completion that an
earlier process did not wait for would otherwise complete the first run at once.

`--mock` and `tb/platform/bw/noop/noop_smoke.sh` check the tool without a card. The latter runs it on XRT's no-op shim with
metadata-only xclbins and checks that a wrong argument offset or size, a missing argument, a wrong control range, two compute
units, an unknown kernel and an oversized buffer are refused. Both run from `tb/platform/bw/test_bw.py` when a `tsr_bw` binary
exists.

## 7. Running on the card

1. Install XRT 2.18.179 with the patched driver and the U200 platform, flash the shell and run `xbutil validate`
   ([platform-u200.md](platform-u200.md) §14 steps 1 to 5).
2. Build `build/u200/bw/tsr_bw_k4.xclbin` with `TSR_VIVADO_LOCK=... hw/u200/bw/build_bw_xclbin.sh`, using the Tesseract kernels'
   m_axi hints as the baseline. The tool prints the xclbin's DATA clock. Rebuild only when the `.xo` manifest no longer matches.
   `TSR_BW_HINTS=wide` builds `build/u200/bw_wide/` for the outstanding sweep with an interconnect sized for 64 and 64.
3. Run `TSR_XCLBIN=build/u200/bw/tsr_bw_k4.xclbin tsr_bw --dry-run`, then `tsr_bw --pcie --sweep-outstanding --ids 1 --csv
   ids1.csv` and `tsr_bw --ids 16 --csv ids16.csv` (the core uses up to 16 IDs per channel), and `tsr_bw --sizes 8G --ch-mib 16384
   --bursts 64 --modes w,r --reps 1 --verify full` for the capacity and aliasing check.

### 7.1 Reading the results

The per-channel and four-channel read, write and read plus write rates at bursts of 64 beats and the core's patterns (weight
stream: 64-beat bursts, DMA LD and ST: up to 64) give the DDR bandwidth the core can use. The outstanding sweep gives the
latency-bound rates and the first-beat latency, and the PCIe rates are the host to card and card to host DMA rates of `xrt::bo`,
which bound the model load time. The capacity check passes when the read of [0, 8 GiB) matches the fill after the write of [8 GiB,
16 GiB), which shows that the channel holds 16 GiB without aliasing. These rates are the yardstick of the performance model
(`docs/spec.md` §17, "Performance verification"). The core's `PERF_*` cycle counters are directly comparable, since the clock and
the bridge are the same. Decode streams every weight byte once per token, so its upper bound is the read bandwidth divided by the
bytes read per token.

## 8. Limits

- The kernel cannot be aborted. A hung run needs `xbutil reset`, and the tool's timeout message says so.
- If the read or write generator loop misses timing in a rebuild, it can be shortened without changing behaviour: the 4 KiB carry
  of a burst is `~z & (lo >= 64 - B)` with a registered threshold, and the next offset is then 0, else `lo + B` or the region end.
  If the per-channel reset copies miss, they need protection from phys_opt's equivalent-driver rewiring.
- `tsr_bw` reads results with the deprecated `xrt::kernel::read_register`, which needs exclusive compute-unit access. On XRT
  versions that drop it, the tool can use `xrt::ip` without `xrt::run` (a register-driven start), and `xrt::ip` cannot share a
  compute unit with `xrt::run`.
- Host to card DMA in `tsr_bw --pcie` writes from a pageable buffer and is slower than the host-pinned buffers of `xrt-smi
  validate`. The transport's `staged` mode (a pinned bounce buffer) is the fast path ([xrt-host.md](xrt-host.md) §4.2).
